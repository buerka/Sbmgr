# 用户分组

管理员在「用户分组」中维护规则和成员。多机部署在主机统一管理，从机继续接收已经解析到用户、设备和节点的策略。普通用户只看自己的状态与订阅，不能查看或修改其他成员及分组。

## 默认分组与继承

升级后已有用户自动进入「默认分组」。初始分组不设置任何统一规则，因此原配额、限速、到期日、线路、身份、用量和登录设置保持不变。默认分组可以改名，不能删除。

每个用户只属于一个分组。分组支持以下四项独立规则，可分别开启：

| 项目 | 作用范围 |
| --- | --- |
| 流量配额 | 每位用户独立使用同样的基础配额和计费方向。例如 100G 表示每人 100 GiB，不是组内共享。附加流量、账期和累计用量保持个人设置 |
| 速度上限 | 设置该用户每个节点的上传、下载 Mbps；0 表示不限速，不合并组内带宽 |
| 到期时间 | 同一有效期最后一天；留空表示长期有效。不改变用户的手动启停状态 |
| 线路授权 | 对用户每台设备分配所选线路；保留仍获授权的节点名称、身份、限速和用量，新线路由程序创建身份 |

关闭某项规则会保留成员当前的值，停止统一更新该项。来源 IP、访问控制、流量保护、附加流量、账期、设备启停和面板登录不属于分组统一设置。

新用户进入默认分组。新建表单留空的配额、限速、到期和线路继承默认分组；分组未配置时沿用原默认行为。明确填写的项作为个人配置。CLI 的显式参数具有相同含义；例如 `--quota 0` 明确要求不限配额。复制用户策略会复制所属分组与覆盖项，但仍重新生成身份与订阅链接，不复制面板密码或累计用量。

## 单用户特殊配置

点击用户列表整行，进入「分组与继承」。四项规则各有「个人配置」选项：

- 勾选：保留该用户当前值，以后修改分组规则不会覆盖这一项。
- 取消勾选并保存：立即采用分组已设置的规则；分组未设置的项保留当前值。
- 在用户其他标签页、CLI 或批量操作中改出与分组不同的值，会在同一次保存中自动标为个人覆盖。即使后来与分组值相同，已记录的覆盖也不会自行消失，需明确切回继承。

线路和速度可以分别覆盖。用户保留个人速度、同时继承分组线路时，新增节点使用该设备已有节点中最低的非零上限；既有节点的速度不变。旧版用户级总限速也继续保留。

仍继承分组速度的用户，通过线路分配或 CLI 新增节点时，新节点沿用分组速度，不会因新增线路变成不限速。CLI 显式指定的新节点速度优先，并在不同时形成个人覆盖。

## 成员移动与保存

在分组的「成员管理」中多选用户，选择目标分组和处理方式。「保留当前配置」是默认选项，会将四项均设为个人覆盖；「继承分组规则」会清除覆盖并采用目标组已开启的规则。也可在用户页移动并逐项选择继承。

保存前页面显示有多少成员继承规则、多少保留个人配置。组规则与全部受影响成员在跨进程锁内一次事务提交；任一成员、线路或数据库校验失败，整批不提交。页面检测并发编辑，冲突时保留输入并要求刷新后重试。累计用量刷新不会制造编辑冲突。

保存后按提示「应用配置」更新运行中的入口策略。新建或修改的线路拓扑应先应用，再用于分组授权。订阅会依据已保存授权生成内容。移除组内线路会撤销相应节点，请先检查影响范围。

删除自建分组前须移出全部成员。程序不隐式删除或迁移组内用户。

## 参数化命令

```sh
sbmgr admin group list
sbmgr admin group save --file group-change.json
sbmgr admin group members --file group-members.json
sbmgr admin group delete --file group-delete.json
```

`list` 返回分组、成员与 `version`。写入请求可带 `expected` 使用该版本做并发校验；Web 写入始终要求版本。文件只在部署方私有目录中保存。

创建组时不传 `id`，修改时使用已有 ID。例如设置每人 100 GiB：

```json
{"name":"标准组","policy":{"quota":{"bytes":107374182400,"mode":"total"}}}
```

成员请求包含 `id`、`users` 和 `mode`。`mode` 为 `preserve`、`inherit` 或 `custom`；`custom` 使用 `overrides` 数组指定 `quota`、`rate`、`expiry`、`routes` 中的个人覆盖项。删除只需要 `id`。更新规则需提供完整 `policy`：省略某项会关闭该项的统一管理。

状态模型版本为 15，SQLite schema 为 6。分组与成员分别保存在结构化表中，使用稳定主键和增量写入；升级仍遵循原有迁移、备份与事务校验流程。
