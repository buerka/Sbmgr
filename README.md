# sbmgr

`sbmgr` 是一个 Go 编写的 sing-box 多用户 CUI 管理器。日常管理只有一个入口：运行程序，然后在界面中完成用户、设备、UUID、出口、配额、到期时间、限速、异常流量保护、来源 IP 绑定和配置导出。

## 部署布局

所有应用文件集中在管理员用户目录：

```text
/root/sbmgr/
├── sbmgr                 # 程序
├── state.json            # 用户、流量、配额等应用数据
├── state.json.lock       # CUI 与后台共享的跨进程事务锁
├── config.base.json      # 保留服务器原有配置的基础模板
├── mihomo.template.yaml  # 每用户导出的完整 Mihomo 母版
├── sing-box.json         # 当前生效的 sing-box 配置
├── audit.jsonl           # 成功的管理操作审计（自动轮换）
├── exports/              # 带时间戳的每用户 Mihomo YAML
├── .drafts/              # 完整 JSON 外部编辑的临时 0600 草稿
├── backups/              # 状态与配置备份（不保存程序版本）
├── deploy/               # 本机部署、IP 证书续期脚本及 unit 模板
├── certbot-venv/         # 独立 Certbot 运行环境（启用公网 HTTPS 后创建）
├── letsencrypt*/         # IP HTTPS 证书、续期配置和工作目录
└── logs/certbot/         # 证书签发与续期日志
```

`state.json` 就是本机数据存储，不需要额外安装或维护数据库服务。它以 `0600` 权限原子写入，便于审阅、备份和迁移。systemd 自身要求服务单元位于 `/etc/systemd/system/`；那里只保留 `sbmgr.service` 和可选的 IP 证书续期 timer/service 定义，不放业务数据或凭据。

## 使用

```bash
/root/sbmgr/sbmgr
```

程序会自动读取与可执行文件同目录的 `state.json`。

CUI 中的更新时间、最后连接、告警、审计和备份时间统一换算为北京时间并显示为 `YYYY-MM-DD HH:MM:SS`；状态文件内部仍保留带时区的 RFC3339 格式，便于程序准确计算和迁移。

### 界面导航

新版界面把功能归入“用户 / 线路 / 运维”三个区域。快捷键仍可作为熟练操作的加速方式，但不再是寻找功能的唯一入口：

- **用户**是默认首页，用于新增、搜索、选择和批量管理用户。进入用户详情后按 `?` 或 `M` 可打开完整的“用户操作”菜单；配额、设备、访问记录、异常保护、来源 IP、重置流量和删除等低频或危险操作都能从菜单进入。
- **线路**在用户首页按 `L` 打开，用于查看和修改中转入口、全部 sing-box 出站/端点以及出口健康状态。旧快捷键 `h` 仍可进入同一页面。
- **运维**在用户首页按 `M` 或 `?` 打开，集中提供告警、订阅交付、状态与配置备份、操作审计、远端管理节点、Mihomo 母版、立即同步和应用配置。

顶部区域名称用于说明当前所在位置；在较窄终端中即使标题被精简，也可以使用首页底部固定显示的 `L 线路/服务器` 和 `M 运维中心` 进入。原来的 `F 多服务器`名称改为“远端管理节点”，它仍然只读取其他 sbmgr 主机的状态，不会修改远端用户或配置。

### 常用快捷键

- `↑/↓` 或 `j/k` 选择，`enter` 查看详情，`/` 搜索；
- 在用户列表按 `space` 勾选/取消用户，`A` 全选当前搜索结果，`C` 清空选择，`B` 打开批量管理；
- `a` 新建普通用户并自动生成第一个独立 UUID；`N` 套用已有用户模板创建新用户；
- `U` 一键解除当前所有临时封禁，确认后自动校验并应用配置；用户详情按 `U` 只解封当前用户；
- `D` 在用户列表直接删除选中用户（会再次确认）；
- `e` 编辑用户的总流量配额和到期时间；
- `b` 设置滑动窗口异常流量保护，可选择软封禁（极低速）或硬封禁（完全断连）；
- `i` 设置来源 IP 存档、单 IP 强制绑定、监控模式或临时换绑；
- `f` 设置允许/禁止域名、禁止端口和最大活跃连接数；
- `c` 查看当前识别到的连接、来源 IP、目标地址、设备和节点；用户详情按 `v` 查看并搜索最近访问网站；
- `!` 在用户列表打开告警中心，查看或标记异常流量及来源 IP 告警；
- `L`（兼容 `h`）打开线路与服务器页面，管理中转入口、落地出口、出口健康与 Webhook 通知；
- `u` 设置每设备订阅服务，设备页按 `u` 可撤销旧链接、按 `z` 显示二维码；
- `o` 查看管理操作审计；
- `F` 查看“远端管理节点”的只读状态汇总；
- `T` 设置或更换完整的 Mihomo YAML 导出母版；
- `v` 打开备份中心，创建或恢复状态备份；
- `m` 打开设备管理；每台设备拥有一组独立 UUID，可单独启停、轮换、绑定 IP 和导出；
- `n` 从服务器节点模板中为选定设备分配节点，并生成独立 UUID；
- `l` 编辑当前选中节点的独立上传/下载 Mbps；
- `x` 选择一台设备并导出独立 Mihomo YAML 到 `exports/`；
- 在用户详情按 `R` 手动重置本月流量（兼容旧快捷键 `t`），按 `space` 启用或禁用；
- `p` 校验并应用配置，`s` 立即同步，`q` 退出。

用户详情先保留计费口径、原始双向流量、当前速度、配额、账期、来源 IP、连接、告警与安全概览，再用一行展示一个节点，只展开当前节点的 UUID、出口、限速和访问摘要。`↑/↓` 或 `j/k` 切换节点，`Home/End` 跳到首尾节点；状态和快捷键栏始终保留在可见区域。非表单、非确认状态下，CUI 每 3 秒重新读取后台快照并保持当前用户、光标和搜索条件，不必退出页面才能看到数字变化。

### 线路与服务器

用户首页按 `L` 进入“线路与服务器”。这里的两个地址用途不同，修改前应先确认是在迁移客户端入口还是服务端落地：

- **中转入口**是写入 Mihomo 导出文件和设备订阅的客户端连接地址与端口，也就是用户首先连接的这台中转机。修改它只更新以后交付给客户端的地址，不会改 sing-box 的监听地址、Reality 密钥、SNI、用户 UUID 或任何落地密码。订阅接口会立即返回新地址，但客户端需要刷新订阅；已经导出的静态 YAML 不会自动变化，需要重新导出。修改此项前应确保新的公网地址和端口确实转发到现有中转入站。
- **落地出口**是 `config.base.json` 中某个远端 outbound tag 的 `server` 和 `server_port`，例如 `to-att`。它决定中转机把对应节点的流量发往哪台落地机。修改落地出口只影响服务端路由，用户 UUID、订阅链接及已经导出的 YAML 都不需要改变或重新下发。

“出站与端点”列表会显示基础模板中的全部 `outbounds` 和 `endpoints`，包括 selector、urltest、WireGuard、Tailscale 以及没有 `server/server_port` 的对象；未知或未来协议也不会被过滤。选中对象按 `Enter` 会打开四项操作菜单：常用字段、完整 JSON、从文件导入和安全删除。按 `e` 可直接进入常用字段表单，按 `a` 可选择“出站/端点”、填写 `tag/type` 后新增对象。

常用字段表单适合日常迁移：带 `server/server_port` 的 outbound 可修改地址和端口，SOCKS/HTTP 还可修改用户名和密码，Shadowsocks 可修改密码。用户名会预填并支持方向键插入编辑；新密码框留空表示保留原密码。密码不会从配置读入表单，输入时全程遮罩，确认页、状态输出和审计日志也不会显示明文。常用表单只修改明确选中的字段，加密方式、TLS、密钥、detour 和其他协议字段原样保留。

完整 JSON 是全协议入口：优先调用 `$VISUAL`、`$EDITOR`，否则使用 `nano` 或 `vi`；也可以填写绝对路径，从现有 JSON 文件导入。编辑草稿只保存在 `/root/sbmgr/.drafts/` 的 `0700` 目录和 `0600` 文件中，CUI 只显示操作、tag、协议、目标和影响数量，不显示任意 JSON 字段值。单个对象限制为 1 MiB、64 层，递归拒绝重复键；替换时不允许暗中改 tag，新增时会检查 outbounds/endpoints 的 tag 全局唯一。未修改对象及系统尚不认识的字段会完整保留。

确认落地变更后，系统会在状态事务锁内执行以下保护：

1. 做本地结构检查：常用表单校验地址、端口和凭据类型；完整 JSON 校验对象、`tag/type`、大小、深度、重复键与全局 tag 唯一性；
2. 在 `backups/` 保存变更前的基础模板，并检测期间是否有其他进程修改原文件；
3. 只更新目标 outbound/endpoint，原子写入 `config.base.json`，再生成包含用户、路由和限速克隆的完整候选配置；删除前会拒绝仍被用户节点、route、detour、selector/urltest、DNS 或其他对象引用的 tag；
4. 使用服务器当前安装的 sing-box 对完整候选执行 `check`，随后校验 nftables 并备份现有 `sing-box.json` 与限速规则；地址变更安全重载，凭据或完整 JSON 变更会重启 sing-box，避免旧连接保留旧认证/旧协议状态；
5. 任一步应用失败时恢复基础模板、运行配置和 nftables 规则，保留备份与错误信息供排查。

服务器当前的 sing-box 版本才是最终协议和字段权威：CUI 不把在线最新版字段硬套给旧二进制，提交时始终由本机 `sing-box check` 验证完整配置；支持 `sing-box schema` 的新版本可另行用本机 schema 辅助编写 JSON。校验器输出会限长，并对 password、username、UUID、私钥、token、auth key 等敏感值脱敏后才显示。

成功切换后会立即刷新出口健康状态。当前健康探测验证的是目标 TCP 端口是否可连接，不等于上游账号密码已经通过认证；切换后仍应通过实际节点请求确认代理认证。落地基础模板备份自动保留最近 20 份；审计日志只记录对象类别、tag、协议、地址端口及凭据是否发生变化，不记录 JSON 或账号密码值。

注意：完整 JSON 可以管理所有 endpoint，但当前“给用户分配节点 + 每节点独立 routing mark 限速”只自动使用 outbound。WireGuard、Tailscale、OpenVPN 等 endpoint 往往包含共享接口和运行状态，不能安全地为每个用户机械复制；因此 endpoint 会显示和校验，但不会被承诺为可独立克隆限速的用户节点。

### 批量管理用户

在用户列表把光标移到需要处理的用户上，按 `space` 勾选；可以先按 `/` 搜索，再按 `A` 全选当前搜索结果。选好后按 `B` 进入批量管理，按类别统一修改：

- 用户状态、流量配额、配额计量方向、附加流量包、到期日、月度账期和阶梯限速；
- 指定节点线路或所有节点的上传/下载 Mbps；
- 异常流量检测窗口、阈值和封禁时间；
- 来源 IP 开关、执行模式、绑定方式、固定/临时 IP；
- 允许/拒绝域名、拒绝端口、最大连接数和超限动作。

批量表单中“保持不变”或留空的字段不会覆盖各用户原值；数值 `0` 仍表示不限或清除对应配额，日期/IP/域名/端口列表输入 `-` 表示明确清除。提交后会显示用户、参数和实际影响数量，再次确认才保存。系统先在内存副本中校验全部选中用户，任何一人不满足规则都会整批取消，不会留下只改了一半的状态；成功操作一次写入 `state.json` 并记录为 `user.batch` 审计事件。保存后按 `p` 应用到 sing-box。

批量选择只存在于当前 CUI 会话，不写入状态文件，也不会改变未勾选用户。长表单会随当前字段自动滚动，在较小终端中仍能看到提交项和状态栏。

服务器原有的 LAX、ATT、Frontier 等凭据不会冒充受管用户，但会作为可分配的节点模板。每个用户只会导出已经分配给他的节点；每台设备、每个节点都有独立 UUID、`auth_user`、出口、上传限速、下载限速和 routing mark。

### 第一次添加用户

1. 在用户列表按 `a`。
2. 输入用户名，例如 `alice`，按 `Enter` 进入下一项。
3. 配额默认 `0` 表示不限；只输入 `200` 会自动按 `200G` 处理。计量默认保持历史行为“上传+下载”，也可改为“仅上传”或“仅下载”。到期日留空表示永不过期。新用户默认启用“动态单活公网 IP”：同一公网 IP 后的多台设备可以同时使用，但同一时刻不能从两个不同公网 IP 使用。
4. 在“初始节点”一栏使用 `←/→` 选择 LAX、ATT 或 Frontier。
5. 为这个初始节点填写上传和下载 Mbps；`0` 表示不限。
6. 最后一项按 `Enter` 创建用户。系统同时创建“默认设备”。进入用户详情后，按 `n` 可继续给设备分配其他节点，仍可分别填写限速；选中节点按 `l` 可随时修改该节点限速，按 `d` 移除授权。

### 套用已有用户模板

用户列表按 `N`，先选择一个已有用户，再填写新用户名即可创建。系统会复制模板用户的配额、到期日、附加流量包、账期、阶梯限速、异常流量保护、来源 IP/访问策略、设备布局、节点出口和每节点限速；新用户默认启用。

模板方式不会复制任何身份或运行数据：所有设备都会获得新的订阅 token，每个节点都会重新生成 UUID、`auth_user` 和 routing mark，累计流量、当前速率、来源 IP 存档、访问历史、告警冷却、账期历史及临时 IP 替代状态全部从零开始。手动指定的固定 IP 会作为配置保留；动态/自动绑定学到的旧用户 IP 会清空并由新用户重新学习。如果新用户不应使用模板中的手动固定 IP，创建后在用户或设备页按 `i` 修改。
7. 回到列表后按 `p`，再按 `y` 应用到 sing-box。
8. 选中用户按 `Enter` 查看详情，再按 `x` 选择设备并导出。配置会按 `/root/sbmgr/exports/用户名-设备-YYYYMMDD-HHMMSS.yaml` 保存，其中只包含该设备已获授权的节点；时间后缀可以避免覆盖之前的文件。

### 完整 Mihomo 母版导出

用户列表按 `T`，填写 `/root/sbmgr/mihomo.template.yaml`，即可把现有通用 Mihomo 配置作为以后所有用户和设备导出的母版。sbmgr 会保留母版中的端口、DNS、规则集、代理组、分流规则和注释，只重建 `proxies`，并把各代理组中的节点引用过滤成该设备真正获授权的节点。母版里的旧 UUID、其他设备 UUID 和未授权节点不会进入导出文件；连接地址、端口、SNI、Reality 公钥和 short ID 使用 sbmgr 当前设置。

节点名称与母版一致时会复用该节点的完整选项，例如 `skip-cert-verify`、`alpn` 等；新增线路没有同名母版节点时，会复用母版中的 VLESS 结构再替换连接凭据。如果某个专用组（例如 `LLM`）原本只包含未授权线路，导出后会安全回退到“节点选择”，避免产生空代理组。未设置母版时仍保留原来的简易导出方式。

母版只影响之后生成的客户端 YAML，不会修改 `config.base.json`、`sing-box.json` 或服务器原有通用凭据。已经导出的旧文件不会自动变化，需要在用户详情重新按 `x` 导出；设备订阅链接会在每次请求时实时使用当前母版。

表单中可用 `↑/↓`、`Tab` 或 `Shift+Tab` 切换字段。编辑普通文本字段时，`←/→` 移动插入光标，`Home/End` 跳到文本首尾，`Backspace` 删除光标前一个字符，`Delete` 删除光标处字符；可以直接在原值中间插入中文或英文，也可以把 IP、URL 或路径粘贴到当前光标位置，不必再从末尾逐字退格重输。超长值保持单行并围绕光标水平滚动，`‹/›` 表示两端还有内容。带固定选项的字段仍使用 `←/→` 切换选项，不会误改成自由文本。`Ctrl+U` 清空当前文本字段，`Esc` 放弃表单；最后一个字段按 `Enter` 提交。清空可选数值后直接提交也会按 `0`（不限）处理。

### 多设备与配置撤销

用户详情按 `m` 进入设备管理。按 `a` 添加“手机”“电脑”等设备时，会复制选定设备已有的节点线路和限速，但为每个节点生成全新的 UUID、`auth_user` 和 routing mark，因此两个设备的配置互不共用凭据。设备页支持：

- `space` 单独启用或禁用设备；
- `r` 轮换该设备全部 UUID，使之前导出的该设备配置失效；
- `i` 为该设备设置独立的公网来源 IP 强制绑定、仅告警或临时换绑；
- `x` 只导出当前设备；
- `D` 删除设备及其全部 UUID。

设备启停、UUID 轮换和删除后需要按 `p` 应用。升级前已有用户会无损迁移到一台“默认设备”，现有 UUID 和 `auth_user` 保持不变。

用户详情会显示配额进度条、每个节点的上传/下载用量，以及选中节点按访问次数排列的目标域名/IP。后台只保存目标地址、聚合次数和最后访问时间，单节点最多保留 50 条，不记录 URL 路径或访问内容；该排行不是按目标流量统计。

用户详情按 `v` 打开“近期访问网站”页。这里按用户、设备、节点和目标聚合最近 7 天的访问，最多保存 1000 个不同组合，并按最后访问时间倒序显示；按 `/` 可以同时搜索网站/IP、设备名或节点名，`Esc` 清除筛选或返回。升级到支持该功能的版本时，会从已有节点访问统计回填近期列表，之后由 sing-box journal 持续增量更新。HTTPS 加密下只能记录域名或目标 IP，不能看到 URL 路径、页面内容或搜索关键词。

配额有三种计量方式：“上传+下载”（默认并兼容所有旧用户）、“仅上传”和“仅下载”。无论选择哪一种，后台始终分别保存并显示真实上传、下载；选择只影响配额进度、80%/95% 阶梯、100% 停用以及订阅客户端的用量进度条，不会丢弃另一方向的审计数据。异常流量滑动窗口仍按双向实际流量计算，避免更改月度计费口径时意外削弱安全保护。

用户设置中的“阶梯限速”默认策略为：按所选计量口径达到 80% 后使用节点基础速度的 50%，达到 95% 后使用基础速度的 20%，达到 100% 后按配额停用。触发百分比和速度百分比均可在 CUI 中修改；节点基础限速为 `0`（不限）时没有可供折算的速度，因此该节点不会被阶梯降速。

用户设置还支持“附加流量包”和按月账期。账期日限定为每月 1–28 日，默认使用 `Asia/Shanghai` 时区；到点后会归档上期上传、下载和当期配额，清零当前统计，并只自动恢复因配额耗尽而停用的用户。最近 24 个账期保留在状态文件中。用量达到 80%/95%，以及到期前 7/3/1 天时会各报告一次，不会每分钟重复告警。到期日按上海自然日计算，当天结束前仍然有效。

用户详情按大写 `R` 可手动重置当前用户的本月流量（旧快捷键 `t` 仍可用）。重置前会先取得实时统计基线，避免下一轮同步把重置前的流量重新加回来；用户与全部节点的上传/下载、当前速率、趋势、异常流量窗口和临时封禁都会清零。基础配额、附加流量包、账期日、下次自动重置日和到期日保持不变；当前已用量会归档为一条未满账期记录，因配额耗尽而停用的用户会恢复，随后立即校验并应用配置。手动重置会写入告警与审计记录。

用户详情中按 `b` 可启用滑动窗口异常流量保护。CUI 的容量输入中，裸数字按 GiB 解释（例如 `2` 等同 `2G`），也可以明确填写 `500M`、`2G` 或 `2GiB`。处罚有两种：

- **软封禁**保留 UUID、连接和全部访问/IP规则，只把该用户所有节点临时压到配置的极低速；默认上传 `16 Kbps`、下载 `2 Kbps`，到期自动恢复各节点原有限速。低速规则采用 4 KiB 小突发，ChatGPT 等 HTTPS 流式响应会变得非常缓慢；由于 TLS/TCP 会按数据包聚合，无法严格保证每次只出现一个字符，但不会像硬封禁一样立即断连。
- **硬封禁**从共享 VLESS 入站中临时移除该用户的全部 UUID，并重启 sing-box 关闭已有连接；封禁期间完全无法连接，到期后自动恢复。

升级到 `0.17.0` 时，已有用户的异常保护统一迁移为软封禁。单用户和批量管理都可以临时切换处罚类型、软封上传/下载 Kbps、窗口、阈值和时长。用户列表按大写 `U` 可一键解除全部处罚，用户详情按 `U` 只解除当前用户；解封不会关闭异常保护，确认后会自动应用配置。触发、解封和恢复都会写入审计与告警中心（用户列表按 `!`）及 `journalctl -u sbmgr` 日志；告警最多保留最近 100 条。自动应用失败时会保留待应用标记，由后台维护周期继续重试。

用户详情中按 `i` 可配置来源 IP 规则。后台通过 sing-box 日志中的连接 ID，把公网源 IP 与认证后的 `auth_user` 对应起来；每个受管用户及每台设备最多各自存档最近 100 个来源 IP，包括首次/最后访问时间、连接次数、最后使用节点和违规次数。用户可以设置覆盖全部设备的一套 IP 绑定，也可在设备管理页按 `i` 为单台设备增加独立规则：

- “动态单活 + 最多 1 个”允许同一公网 IP（包括同一 NAT 后的多台设备）建立任意多个连接；默认只在当前已绑定 IP 最近 60 秒仍有活动时阻止换绑，时间可在 1–3600 秒间自定义。旧 IP 静默超过等待时间后，新 IP 下一次重试会在最多约 5 秒内接管并触发安全重载；被拒绝的新 IP 不再被误当成相互竞争的活跃连接；
- “强制限制 + 自动绑定 + 最多 1 个”会把第一次观察到的公网 IP 设为固定 IP，随后由 sing-box 原生 `auth_user` + `source_ip_cidr` 路由规则拒绝其他 IP；
- “仅记录告警”只存档和报告，不拒绝连接，适合先观察动态公网 IP；
- “手动指定”可直接填写一个或多个固定 IP；固定 IP 为空时，强制模式会拒绝该用户全部连接；
- “临时替代 IP”会在设定分钟内替换固定绑定，到期后自动恢复，适合出差或临时更换网络；
- 动态首次绑定和换绑由约 5 秒一次的轻量同步处理；首次连接可能先失败一次，客户端正常重试后即可使用。规则落地后，未授权来源的新连接会立即拒绝；只有允许 IP 集合真实变化时才重载 sing-box，并在成功后清除旧连接快照。

用户级与设备级规则会叠加执行：同一连接必须同时满足两层已启用的强制规则，系统不会用较宽松的设备规则绕过用户规则。这里记录和限制的是服务器看到的公网出口 IP，不是设备内网地址。同一 NAT 下的多台设备会显示为同一个 IP；移动网络或家庭宽带经常换公网 IP 时，可缩短“换网静默等待”、改用仅告警模式、提高允许数量，或使用临时替代 IP。服务器原有未受管凭据不会被自动归到新用户，只有 sbmgr 创建并导出的用户配置会参与存档和限制。

### 访问规则与并发保护

用户详情或设备页按 `f` 可分别配置允许域名、禁止域名、禁止端口与最大活跃连接数。规则由 sing-box 按对应 `auth_user` 执行，不会影响原有未受管凭据，也不会串到其他用户或设备。填写允许域名后会变成严格白名单；域名支持后缀匹配，禁止端口支持逗号分隔。并发超限可选择仅告警、禁用当前设备或禁用整个用户；后台应用禁用后会重载配置来断开旧连接。规则可随时在 CUI 临时修改或关闭。

### 订阅链接与二维码

用户列表按 `u` 打开订阅交付总览。每台设备获得独立的高熵 token：`/sub/<token>` 返回只含该设备节点的 Mihomo YAML，`/qr/<token>.png` 返回二维码。总览可选择设备、显示二维码或轮换 token；设备页也保留相同操作。轮换后旧链接立即返回 404。接口禁止缓存并带有基础 IP 频率限制，token 本身就是访问凭据，不应发到公开群聊。

成功返回的订阅会带 `Subscription-Userinfo`、`Profile-Update-Interval` 和 `Profile-Title` 响应头。支持这些响应头的 Mihomo 面板会在配置卡片下显示已用/总量、进度和到期时间；只上传/只下载模式会只把被计费方向写入用量头，避免客户端进度与服务端处罚进度不一致。HTTP 下载文件名会使用 `用户-设备-YYYYMMDD-HHMMSS.yaml`，而稳定的 `Profile-Title` 不带时间，避免客户端每次更新都把同一订阅识别成新配置。静态导出的 YAML 是文件快照，不会自动刷新，也没有动态响应头。

服务默认关闭且只监听 `127.0.0.1:18080`。sbmgr 可以直接读取证书和私钥提供原生 HTTPS；一旦监听非回环地址便强制要求 TLS，公网基础 URL 也强制使用 HTTPS。当前部署可使用高位端口 `8443`，不会占用 sing-box 的 `443`。如继续使用同机反向代理，限流来源 IP 只会在直接连接来自回环地址时读取由代理覆盖写入的 `X-Real-IP`；程序明确忽略可被客户端预置的 `X-Forwarded-For`。例如 Nginx 应使用 `proxy_set_header X-Real-IP $remote_addr`，不要把客户端提供的同名头原样透传。公网直连请求的转发头一律不受信任。不要公开 `/root/sbmgr` 或管理界面。

Let’s Encrypt 的 IP 地址证书属于约 6 天的短期证书，必须自动续期。`deploy/setup-ip-https.sh PUBLIC_IP 8443 [EMAIL]` 会在 `/root/sbmgr` 内创建独立的 Certbot 5.4+ 环境；Debian/Ubuntu 缺少 Python venv 组件时会先安装 `python3-venv`。脚本通过空闲的公网 TCP/80 完成验证，把证书也保存在应用目录，并启用每天两次的 `sbmgr-ip-cert-renew.timer`；续期成功后只重启 sbmgr 订阅服务，不改 sing-box。云厂商防火墙需要允许 TCP/80（签发/续期）和所选 HTTPS 高位端口（客户端下载）。

### 实时与历史观察

后台约每 5 秒同步 nftables 计数、用户/节点当前上传下载 Mbps、访问记录与动态 IP 状态，并保存稀疏历史点；完整的配额、账期、健康、通知和多服务器维护仍按分钟执行。用户详情按 `c` 可查看 sing-box journal 中关联到受管 `auth_user` 的活跃连接，包括设备、节点、来源 IP、目标和开始时间；已关闭或长时间静默的记录会自动清理。“线路与服务器”页可自动探测配置中远端出口的 TCP 连通性和延迟，也可为 tag 手动指定 `host:port`。连续失败、恢复、配额、到期、异常流量、IP 违规和远端管理节点离线等告警可以 POST 到自定义 Webhook，密钥以 Bearer token 发送。

## 后台服务

`sbmgr.service` 是唯一处理用户与流量状态的应用后台单元；可选证书 timer 只调用 Certbot，不读取或修改用户。后台约每 5 秒做轻量计数/访问/IP 刷新，并每分钟执行以下完整维护：

1. 服务器重启后恢复 nftables 实时限速和用量计数规则；
2. 同步用户及节点上传/下载用量，并在跨越阈值时更新阶梯限速或执行异常流量临时封禁；
3. 增量读取 sing-box journal，聚合受管节点访问目标，并关联、存档和检查用户及设备公网来源 IP；
4. 检查流量配额和到期时间，必要时禁用用户并安全应用配置；
5. 维护账期重置、配额/到期里程碑、当前 Mbps、历史曲线、活跃连接与访问规则；
6. 探测出口与远端 sbmgr 状态，并重试发送 Webhook 告警；
7. 在 sing-box 支持并启用 V2Ray gRPC API 时可改用其流量统计。

服务异常会自动重启。查看状态和日志：

```bash
systemctl status sbmgr
journalctl -u sbmgr
```

## 状态一致性与恢复

CUI、后台同步和隐藏维护入口对 `state.json` 的完整“读取—修改—保存”事务共用一把跨进程文件锁，避免后台统计覆盖用户刚刚修改的数据。状态加载会执行版本迁移和结构校验；重复用户名、重复 `auth_user`/UUID、无效策略或负流量会被拒绝保存。

每次状态真正变化前都会更新 `backups/state.previous.json`，每天第一次变化前还会保留 `state-YYYYMMDD.json`，自动保存最近 14 天。用户列表按 `v` 可创建手动备份或选择备份恢复，手动状态备份保留最近 20 份；恢复前系统会再创建一份安全快照，并在恢复后先校验再应用 sing-box 配置。若应用失败，状态、sing-box 配置和 nftables 规则都会恢复到操作前。

每次成功的人工管理操作会追加到 `audit.jsonl`，记录时间、系统账号、动作、参数和进程号；UUID、订阅 token、私钥和 Webhook 密钥会自动脱敏，后台周期统计不会制造审计噪声。日志达到 5 MiB 后轮换为 `audit.previous.jsonl`。

sbmgr 不下载、保存、切换或回滚自身二进制，CUI 和隐藏维护命令中也没有软件版本管理入口。源码版本由 Git commit/tag 管理；`sbmgr version` 只显示构建时写入的版本标识。外部部署脚本只在一次部署事务中临时复制当前二进制，部署失败时自动还原，成功后立即删除临时副本。跨版本回退应在 Git 中检出目标 tag、重新构建并使用外部部署脚本安装。

程序自身只管理业务恢复材料：`state.json` 的自动/手动快照、变更前的 `config.base.json`、上一份 `sing-box.json` 和限速规则。它们与源码版本相互独立，因此恢复用户或配置不会暗中替换程序，切换 Git 版本也不会覆盖现有用户数据。

“运维中心 → 远端管理节点”（兼容快捷键 `F`）可添加其他 sbmgr 主机做只读汇总，查看版本、用户/设备数、累计流量、告警和在线状态。远端查询使用非交互 SSH、5 秒连接超时并严格校验 `known_hosts`，只执行 `admin snapshot`，不会远程改用户或配置。密钥必须使用本机绝对路径。

## 安全应用

界面中的“应用配置”会先生成候选文件并运行 `sing-box check`。校验通过后，它会更新自身的 nftables 表，将上一版配置写入 `backups/sing-box.previous.json`，再原子替换 `sing-box.json`。若服务重载失败，会尝试恢复上一版配置。systemd 单元同时启用只读系统目录、只读 home、私有临时目录、禁止提权和 capability 白名单；只有 `/root/sbmgr` 保持可写。

备份、导出、状态和运行配置都留在 `/root/sbmgr/`，不会再分别写到 `/etc/sbmgr`、`/var/backups/sbmgr` 和 `/usr/local/bin`。

## 实时限速

共享 VLESS 443 入站中的加密包无法由 Linux `tc` 直接识别 UUID。sbmgr 在 sing-box 完成认证后，根据每台设备每个节点 UUID 对应的 `auth_user` 选择带有独立 `routing_mark` 的专属出站，再由 nftables/conntrack 对该设备的该节点执行上传和下载限速。同一用户、不同设备的 LAX、ATT、Frontier 都可以设置不同 Mbps，总公网入口仍然只有 443。

运行要求是 Linux、nftables、conntrack，以及支持出站 `routing_mark` 的 sing-box。普通节点限速采用 128 KiB 突发以兼容 GRO/GSO；软封禁改用 4 KiB 小突发，使短小的 HTTPS 流式响应也受到处罚。两者都采用 policing：TCP 会通过丢包反馈降速，UDP 超额包会被丢弃。用量计数位于超速丢弃规则之后，只累计实际放行的线上字节；重建 nftables 表时会继承现有计数，避免应用配置造成统计跳零。

按 `p` 应用配置时会先分别校验 sing-box 与 nftables，再备份当前配置和限速表。写入、重载或重启任何一步失败时，程序会恢复旧配置、旧 nftables 表并重新加载原服务，避免状态、配置和实时限速只成功一半。

## 构建

```bash
go test ./...
./deploy/build-linux.sh
```

`deploy/build-linux.sh` 只接受干净工作树中精确指向 `HEAD` 的 `vX.Y.Z` tag，从该 tag 和 commit 生成版本信息并通过链接参数写入二进制；没有正式 tag 或存在未提交改动时会拒绝发布构建。`sbmgr version --verbose` 可同时核对构建版本与完整 Git commit。需要 Go 1.25 或更新版本。安装和业务状态恢复仍保留隐藏的 `admin` 维护入口，但不会出现在日常帮助中；程序版本回退不属于该入口。

完整开发、测试、发布和部署流程见 `docs/DEVELOPMENT.md`；架构与安全边界见 `docs/ARCHITECTURE.md`。面向 AI 编码工具的项目约束位于仓库根目录 `AGENTS.md`。

## 功能边界

sbmgr 当前负责单机用户、设备、节点、流量策略、订阅和只读多机状态，不包含支付下单、自动收款或第三方账号系统。远端管理节点页不会批量修改远端配置；需要先分别部署相同版本并建立可信的 SSH `known_hosts`。共享 443 入站的实时限速依赖 Linux nftables/conntrack，无法在不支持 routing mark 的平台上工作。
